# ТЗ: перенос пульта на свой сервер и интеграция с Битрикс24 / amoCRM

## 1. Цель

Перенести прототип `index.html` из Claude на инфраструктуру агентства так, чтобы:
- сделки, лиды, звонки и задачи приходили из CRM автоматически, без двойного ввода;
- SLA «звонок за 15 минут» считался от реального поступления заявки и по данным телефонии;
- сотрудники входили через аккаунт Битрикс24 (или amoCRM), без отдельных аккаунтов Claude;
- персональные данные клиентов хранились в РФ (152-ФЗ, ст. 18 ч. 5 — согласовать с юристом);
- РОП и агенты получали уведомления (Битрикс24 / Telegram).

Логика пульта (баллы ЕКА, план и run rate, P&L, прогноз денег, оценка РОПа, распределение лидов, проверки) переносится без изменений — см. `architecture.md`.

## 2. Целевая схема

```
Битрикс24 / amoCRM ──(REST API + вебхуки событий)──► Сервер пульта (РФ) ──► PostgreSQL
                                                        │   ├─ REST/WebSocket API для фронтенда
Телефония ──(события звонков)──────────────────────────►│   ├─ планировщик (утренние повестки, напоминания 18:30, SLA)
                                                        │   └─ LLM-шлюз (ключ только на сервере)
Фронтенд = index.html (адаптер вместо window.claude) ◄──┘
   └─ открывается как приложение во вкладке Битрикс24 или по своему домену
```

Хостинг: Yandex Cloud / Selectel / VK Cloud (РФ). Бэкенд — на выбор подрядчика (Node.js / Python), БД — PostgreSQL.

## 3. Работы

### 3.1 Адаптер данных (фронтенд)
Заменить `window.claude.use('db' | 'user' | 'sample' | 'downloads')` на модуль с тем же интерфейсом:
- `db.collection(path).onSnapshot/add/where/orderBy/limit`, `db.doc(path).get/set/update/delete` → REST + WebSocket (или SSE) для живых обновлений;
- `user.me()` → `{id, role, office, agentId}` из сессии;
- `sample(prompt)` / `sample.json(prompt)` → `POST /api/ai`;
- `downloads.save` → скачивание файла.
Объём: ~10–15% кода, остальная логика без изменений.

### 3.2 Сервер и БД
- Таблицы по коллекциям из `architecture.md` (leads, agents, exclusives, reports, settings, finance, ai, audits, hr) + users (id, crm_user_id, role, office, agent_id).
- Права на сервере (не только в интерфейсе): агент — только свои сделки и отчёты; РОП — свой офис; финансы — только собственник.
- Аудит-лог изменений (кто, что, когда).
- Ежедневный бэкап.

### 3.3 Интеграция с Битрикс24
Приложение Битрикс24 (локальное или тиражное), OAuth 2.0.

| Задача | Методы / события REST Битрикс24 (сверить с актуальной документацией) |
|---|---|
| Первичная загрузка | `crm.deal.list`, `crm.lead.list`, `crm.contact.get`, `crm.status.list` / `crm.dealcategory.stage.list` (этапы), `user.get` |
| Обновления в реальном времени | `event.bind`: `ONCRMLEADADD`, `ONCRMDEALADD`, `ONCRMDEALUPDATE`, `ONCRMACTIVITYADD`, `ONTASKUPDATE` |
| Звонки | `ONVOXIMPLANTCALLEND`, `voximplant.statistic.get` (длительность, время первого звонка по лиду) |
| Запись из пульта в CRM | `crm.deal.update` (этап, ответственный), `crm.activity.add` / `tasks.task.add` (задачи), `crm.timeline.comment.add` |
| Уведомления | `im.notify.system.add` / бот в чате Битрикс24 |
| Встраивание | `placement.bind` — вкладка пульта в портале и в карточке сделки |

Сопоставление: этапы воронки «Сделки» из ТЗ Битрикс24 ↔ new/meet_set/meet_done/negot/deposit/mortgage/contract/won/lost; ответственный ↔ agentId; источник, направление, БАНТ, комиссия, банк ипотеки — пользовательские поля (UF_CRM_*), список согласовать.

### 3.4 Интеграция с amoCRM (если используется)
| Задача | API v4 amoCRM |
|---|---|
| Загрузка | `/api/v4/leads`, `/contacts`, `/leads/pipelines`, `/users`, `/tasks` |
| События | вебхуки: добавление/смена статуса/ответственного сделки, задачи, примечания-звонки |
| Запись | `PATCH /api/v4/leads`, `POST /api/v4/tasks`, примечания |
| Встраивание | виджет amoCRM (вкладка / карточка) |

### 3.5 Расписание (сервер)
- 08:45 — утренние повестки планёрок по офисам (LLM);
- каждые 5 минут — проверка SLA с учётом рабочих часов (настройка), уведомление РОПу;
- 18:00 — напоминание об отчёте, 18:30 — сводка РОПу;
- пятница — недельный разбор РОПов для собственника;
- ночью — пересчёт баллов ЕКА и лимитов лидов на завтра.

### 3.6 ИИ
Все промпты — в `index.html` (`PROMPTS`, `generateAgenda`, `generateRopReview`, скрипты `SCRIPTS`). Перенести на сервер. До начала работ проверить доступность выбранного LLM-провайдера и условия его использования для компании в РФ; при необходимости — российский провайдер.

## 4. Этапы и приёмка

| Этап | Результат | Критерий приёмки |
|---|---|---|
| 1. Сервер, БД, адаптер, вход | пульт работает вне Claude на демо-данных | все разделы открываются под тремя ролями, права проверены на API |
| 2. Импорт и синхронизация CRM | сделки и лиды из CRM в пульте ≤ 1 мин после изменения | 50 тестовых изменений без расхождений |
| 3. Телефония и SLA | время первого звонка из телефонии | отчёт SLA совпадает с выгрузкой телефонии |
| 4. Уведомления и расписание | повестки, напоминания, сводки | 5 рабочих дней без пропусков |
| 5. Пилот | один офис 2 недели | сравнение «до/после» по метрикам пилота |

Ориентир по срокам: 2–4 недели разработки для этапов 1–4.

## 5. Что передаётся подрядчику
- этот репозиторий (`index.html`, `docs/`);
- доступ к тестовому порталу Битрикс24 / аккаунту amoCRM;
- регламенты агентства (CRM, РОП, ЕКА, эксклюзив, планёрки) — источник бизнес-правил.
