# Как запустить пульт на своём сервере

Пошагово, без программирования. Займёт около часа. В итоге пульт будет открываться по вашему адресу (например, `https://pult.ruban-nedv.ru`), сотрудники входят по логину и паролю, данные хранятся на сервере в России.

## Что понадобится

| Что | Где взять | Ориентир по цене |
|---|---|---|
| Сервер (VPS) в РФ: Ubuntu 24.04, 1–2 ядра, 2 ГБ памяти, 20 ГБ диска | Timeweb Cloud, Selectel, Yandex Cloud, REG.RU Облако | несколько сотен рублей в месяц — сверьте на сайте провайдера |
| Домен (необязательно, но нужен для HTTPS) | REG.RU, RU-CENTER и т. п. | от ~200 ₽ в год |
| Доступ к репозиторию на GitHub | github.com/cc-system-ru/nedvishimost-pult | — |
| Ключ ИИ (необязательно) | см. шаг 6 | по тарифу провайдера |

## Шаг 1. Создайте сервер

В панели провайдера: «Создать сервер» → образ **Ubuntu 24.04** → минимальная конфигурация (2 ГБ RAM) → регион в России. После создания провайдер покажет **IP-адрес** и **пароль root** (или пришлёт на почту).

## Шаг 2. Привяжите домен (если есть)

В панели регистратора домена создайте запись:
- тип **A**, имя **pult** (или @ для основного домена), значение — **IP сервера**.

Запись начинает работать через 5–60 минут. Без домена пульт будет открываться по `http://IP` — для пилота можно, но без шифрования.

## Шаг 3. Подключитесь к серверу

- **Windows:** откройте «Терминал» (или PowerShell) и введите `ssh root@IP_СЕРВЕРА`
- **Mac:** программа «Терминал», та же команда.

Введите пароль (символы не отображаются — это нормально). Также многие провайдеры дают «консоль» прямо в браузере — можно работать там.

## Шаг 4. Скачайте код

Репозиторий приватный, поэтому нужен токен GitHub:
1. GitHub → аватар → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.
2. Repository access: **Only select repositories → nedvishimost-pult**; Permissions → **Contents: Read-only**. Сохраните токен.

На сервере выполните (подставьте свой логин GitHub и токен):

```bash
apt-get update && apt-get install -y git
git clone https://ЛОГИН:ТОКЕН@github.com/cc-system-ru/nedvishimost-pult.git /opt/pult
```

## Шаг 5. Установите пульт одной командой

С доменом:
```bash
sudo bash /opt/pult/deploy/install.sh pult.ваш-домен.ru
```
Без домена:
```bash
sudo bash /opt/pult/deploy/install.sh
```

Скрипт сам поставит Node.js, приложение, службу автозапуска и веб-сервер Caddy (он же выпускает бесплатный HTTPS-сертификат). В конце покажет адрес.

Откройте адрес в браузере → пульт попросит **создать учётную запись собственника** (имя, логин, пароль). Это делается один раз.

## Шаг 6. Подключите ИИ (по желанию)

Без ИИ пульт полностью работает, просто скрыты ИИ-кнопки (повестки планёрок, разборы, скрипты под клиента). Чтобы включить:

```bash
nano /opt/pult/.env
```
Раскомментируйте (уберите `#`) один из вариантов и вставьте ключ:
- **Anthropic (Claude):** `LLM_PROVIDER=anthropic`, `LLM_API_KEY=...`, `LLM_MODEL=...`. Россия не входит в список регионов, где Anthropic официально предоставляет API, — проверьте возможность и условия использования для вашей компании до подключения.
- **Сервис с OpenAI-совместимым API** (например, YandexGPT в Yandex Cloud): `LLM_PROVIDER=openai`, адрес, ключ и модель — из документации сервиса.

Сохраните (Ctrl+O, Enter, Ctrl+X) и перезапустите: `systemctl restart pult`.

## Шаг 7. Добавьте сотрудников

В пульте слева — кнопка **«Сотрудники»** (видна только собственнику):
1. Добавьте РОПов (роль «РОП») и агентов (роль «Агент»), задайте логины и временные пароли, передайте их лично.
2. В пульте на вкладке РОП добавьте агентов с планами (если ещё не добавлены).
3. РОП при первом входе выбирает свой офис.
4. Агент при первом входе выбирает себя в списке — РОП подтверждает в блоке «Доступы». После этого агент видит только свои сделки. Это проверяется на сервере, не только на экране.
5. Удалите демо-данные кнопкой вверху пульта, когда начнёте работать с настоящими клиентами. Чтобы демо не загружалось вообще, поставьте `SEED_DEMO=0` в `.env` до первого запуска.

## Обслуживание

| Задача | Команда |
|---|---|
| Обновить пульт до последней версии из GitHub | `sudo bash /opt/pult/deploy/update.sh` |
| Перезапустить | `systemctl restart pult` |
| Посмотреть журнал ошибок | `journalctl -u pult -n 100` |
| Резервные копии | создаются сами раз в сутки в `/opt/pult/data/backups`, хранятся 14 дней. Скачивайте их себе раз в неделю (например, программой WinSCP / FileZilla). |
| Восстановить из копии | `systemctl stop pult && cp /opt/pult/data/backups/pult-ГГГГММДД.db /opt/pult/data/pult.db && rm -f /opt/pult/data/pult.db-wal /opt/pult/data/pult.db-shm && chown pult:pult /opt/pult/data/pult.db && systemctl start pult` |
| Забыли пароль собственника | другой собственник меняет его в «Сотрудниках»; если собственник один — напишите разработчику |

## Перенос данных из пульта в Claude на свой сервер

В пульте в Claude нажмите «Выгрузить в Excel» — файл останется у вас как архив. Автоматический перенос базы из Claude можно сделать отдельно: данные выгружаются в JSON и загружаются в новую базу (формат тот же, что в `app/seed/demo.json`).

## Альтернатива: Docker

Если на сервере уже есть Docker: `cp .env.example .env`, затем `DOMAIN=pult.ваш-домен.ru docker compose up -d --build`. Учтите, что Docker Hub из России может быть недоступен — тогда используйте `install.sh`.
